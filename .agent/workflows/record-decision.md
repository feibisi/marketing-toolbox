# 记录设计决策工作流

此工作流在遇到设计系统规范未覆盖的情况时触发。

## 触发条件

当 AI 代理遇到以下情况时触发：
- 现有规范没有明确规定的设计问题
- 需要在多个方案之间做选择
- 发现规范有冲突或需要补充
- 用户提出了新的设计需求

## 执行步骤

### 1. 确认规范覆盖情况

首先检查现有文档是否有相关规定：

// turbo
```
view_file docs/DESIGN_RULES.md
```

如果需要更详细信息：
// turbo
```
grep_search "关键词" docs/DESIGN_SYSTEM.md
```

### 2. 检查是否有先例

查看是否有类似的设计决策：
// turbo
```
view_file docs/DESIGN_DECISIONS.md
```

### 3. 询问用户

如果确认无先例，**必须询问用户**：

```markdown
🤔 **设计决策需要确认**

**问题**: [描述遇到的问题]

**可选方案**:
1. 方案A: [描述] - 优点/缺点
2. 方案B: [描述] - 优点/缺点

**建议**: [AI的建议及理由]

请确认您希望采用哪个方案？
```

### 4. 记录决策

用户确认后，在 `docs/DESIGN_DECISIONS.md` 添加新记录：

**必填字段**:
- `DEC-XXXX`: 决策ID（递增）
- `日期`: 当前日期
- `状态`: ✅ 已批准
- `标签`: 使用 `#layout` `#color` `#spacing` 等分类
- `影响范围`: 受影响的组件/工具
- `问题背景`: 描述问题
- `决策内容`: 描述解决方案
- `代码示例`: CSS/HTML/JS 示例
- `理由`: 为什么选择这个方案
- `后续行动`: 需要更新的文档清单

### 5. 更新决策索引

在 `DESIGN_DECISIONS.md` 的索引表中添加新行。

### 6. 更新关联文档（如适用）

如果决策具有通用性：

**更新 DESIGN_RULES.md（如果是必遵规则）**:
- 添加到相应分类
- 提供正确/错误示例

**更新 DESIGN_SYSTEM.md（如果需要详细说明）**:
- 在相关章节添加规范
- 提供完整代码示例

**更新 GOLDEN_EXAMPLES.md（如果产生了新范例）**:
- 添加到功能模式表
- 提取关键代码片段

## 决策ID规则

- 格式: `DEC-XXXX` (4位数字)
- 从 `0001` 开始递增
- 查看当前最大ID:
```
grep "### DEC-" docs/DESIGN_DECISIONS.md | tail -1
```

## 注意事项

- **永远不要在没有用户确认的情况下记录决策**
- 被拒绝的方案也要记录（状态标记为 ❌ 已拒绝）
- 决策记录要包含足够的上下文，让未来的开发者能理解原因
