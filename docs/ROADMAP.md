# Long-term Roadmap

> [CX] 记录日期：2026-08-13  
> 状态：长期实施路线。阶段顺序已确定；具体日期、人员、预算、线上地址和商业承诺仍需分别确认。

## 目标

把 Marketing Toolbox 从 144 个可浏览页面深化为一套独立、local-first、可打印、可复核的营销项目工作台。长期价值来自 6 条工作流、30 个核心工具、版本化项目数据和可信交付物，而不是持续增加同义画布。

`modiqi.com` WordPress 主站承担获客、内容、品牌和服务转化；工具箱承担实际工作流和本地项目交付。主站不能成为工具箱运行依赖，也不能读取本地画布数据。

## 当前基线

- 144 个工具已有规范化清单；30 个核心工具按 6 条工作流组织。
- 桌面 144、移动 144、核心打印 30 个布局样本的已知阻断项已清零。
- 日常 `npm run test:quality` 已覆盖清单、数据合同、依赖、语法、静态引用、CSS、浏览器和布局。
- 30 个核心工具当前仍处于 `smoke`，不是正式发布状态。
- 715 个 CSS 设计令牌 warning 是未完成债务。
- 当前验证以本地自动化和合成/技术样本为主，不能代替真实业务成效验证。

## 阶段 1：建立可维护基线

**目的**：让仓库、质量证据和变更过程可重复。

- 建立 README、贡献、安全、治理、路线和项目级变更记录。
- 固定 `main`、短期分支、合并请求、版本候选和发布授权边界。
- 排除依赖、浏览器产物、导出文件和本地凭据，保留可复核机器报告。
- 建立秘密扫描、依赖更新候选和文档链接检查；是否接入 FeiCode 自动化需在 runner 可用后验证。
- 将当前本地门禁作为基线，禁止通过放宽检查消除债务。

**退出门槛**：新环境能按文档安装并运行统一门禁；仓库不含已知敏感资料；分支保护和自动化的实际状态有独立记录。

## 阶段 2：深化 30 个核心工具

**目的**：从“页面可用”转向“结论可复核”。

按 6 条工作流逐批处理，每个核心工具补齐：

- 适用问题、非适用边界和目标角色；
- 必需输入、数据来源、事实/假设/待验证状态；
- 公式、推导方法、空值/边界行为和业务断言；
- 完成标准、上游/下游字段和报告映射；
- 导入导出、打印、移动端、键盘和多浏览器样本；
- 至少一组经授权、脱敏且来源明确的真实业务样本，或明确记录为缺失。

同时按工作流迁移 715 个设计令牌 warning，不增加债务基线。

**退出门槛**：30 个核心工具逐项达到 `review`，每项都有合同、自动化、打印证据和样本来源；零真实样本的项目不得进入 `release`。

## 阶段 3：形成跨工具交付链

**目的**：用户得到一套项目成果，而不是 30 份孤立画布。

- 版本化跨工具字段、证据、假设、负责人、复核日期和引用关系。
- 建立向后兼容的项目迁移、冲突处理、备份和恢复测试。
- 让报告只汇总已确认、有来源且在有效期内的结论。
- 为 6 条工作流建立开始条件、完成条件、缺口提示和项目包输出。
- 对 JSON、图片、PDF 和打印输出建立稳定的版本与来源标记。

**退出门槛**：每条工作流可从项目语境完成到可复核报告；迁移、恢复和降级失败均有测试；报告不把假设自动写成事实。

## 阶段 4：建设主站增长与内容系统

**目的**：通过 `modiqi.com` 为独立工具箱带来可测量流量，并将高意向用户引向合适服务。

- 30 个核心工具优先建立完整、权威的资源入口；114 个扩展工具先使用结构化目录页，按搜索、使用和转化数据决定是否深化。
- 建立 6 个工作流主题入口，以及围绕真实问题、案例和搜索意图的文章集群。
- 服务落地页对应工作流/解决方案，不机械地为 144 个画布各复制一套落地页。
- 主站和工具箱只交换稳定工具 ID、标题、等级、工具链接、营销链接和工作流 ID 等公开字段。
- 建立跨域/跨站测量的事件字典、UTM 规则、同意与隐私边界；不传输画布正文或项目数据。
- 根据收录、有效访问、工作流启动、完成、导出和合格咨询建立升降级规则。

**退出门槛**：公开入口状态、canonical、结构化数据、分析事件和隐私说明经过各自验证；计划 URL 与实际发布 URL 可区分；没有批量低价值内容被当作完成量。

## 阶段 5：验证项目包和商业闭环

**目的**：验证工具箱是否提高营销咨询交付质量，而不是只提高页面访问量。

候选项目包包括品牌定位、GTM、内容增长、SEO 审计、漏斗诊断和销售赋能。每个项目包需明确：

- 购买者、使用者、收费对象和业务问题；
- 固定工作流、核心工具、输入样本、完成标准和报告模板；
- 服务责任、数据处理、时间范围、价格假设和停止条件；
- 意向、付费试点、真实交付、复购和成效分别记录。

**退出门槛**：至少有经授权的真实项目样本支撑工作流质量判断；商业结论不以访问量、候选页面或合成案例替代付费和复购证据。

## 条件路线：协作与服务端能力

账户、云同步、多人权限、在线共享、服务端生成或 AI 辅助不是默认阶段。只有以下条件明确后才进入技术选型：

- 实际多人场景和付费需求；
- 数据所有权、区域、留存、导出、删除和审计责任；
- 权限模型、组织隔离、加密、备份和事故响应；
- 运行预算、维护负责人、SLA 假设和退出/迁移方案。

在此之前保持静态、local-first 架构，避免为了未来假设引入账户和服务端复杂度。

## 不做事项

- 不用继续增加工具数量掩盖核心工具深度不足。
- 不为 144 个工具批量生成同质文章和落地页。
- 不让 WordPress 读取画布数据或成为工具运行前置条件。
- 不在真实需求和数据治理未确定前建设客户库、云同步或多人后台。
- 不把自动化门禁、本地 HTTP 200、版本号或仓库推送写成已部署、已商业验证或已形成成效。

## 阶段评审指标

每次阶段评审至少记录：

| 维度 | 证据 |
|---|---|
| 产品 | 核心工具 readiness、工作流完成条件、未满足门槛 |
| 正确性 | 公式断言、边界样本、真实样本数与来源 |
| 交付 | 完成、导出、打印、报告引用和恢复样本 |
| 质量 | 自动化退出码、浏览器/打印范围、CSS warning 变化 |
| 内容增长 | 已发布且收录的入口、有效访问、工作流启动和合格转化 |
| 安全隐私 | 依赖、导入、存储、秘密、权限和事件处理记录 |
| 商业 | 意向、付费试点、真实交付和复购，分别统计 |

没有样本的指标写 `SKIP` 或 `BLOCKED` 并说明原因，不写 `PASS`。
