### DEC-0001: 紧凑布局变体

**日期**: 2026-01-02  
**状态**: ✅ 已批准  
**标签**: `#layout` `#overflow`  
**影响范围**: 类型分析模块、所有网格卡片布局

#### 问题背景
`content-performance.html` 页面底部的类型分析模块使用5列垂直卡片网格，导致页面超出A3画布114px溢出。需要在不丢失信息的前提下压缩高度。

#### 决策内容
创建 `.compact` 布局变体类，将垂直堆叠的卡片转换为水平内联行：

#### 代码示例
```css
/* 标准布局: 垂直卡片 */
.type-analysis .type-grid {
    display: grid;
    grid-template-columns: repeat(5, 1fr);
}

/* 紧凑布局: 水平行 */
.type-analysis.compact .type-grid {
    display: flex;
    flex-wrap: wrap;
    gap: var(--spacing-sm);
}

.type-analysis.compact .type-card {
    flex: 1;
    flex-direction: row;
    align-items: center;
    padding: var(--spacing-sm);
}
```

#### 理由
1. 布局模式切换比简单压缩间距更有效
2. 水平布局更适合展示简单的类型+数量信息
3. 可复用于其他类似场景

### DEC-0002: 溢出处理优先级

**日期**: 2026-01-02  
**状态**: ✅ 已批准  
**标签**: `#overflow`  
**影响范围**: 所有工具的溢出处理

#### 问题背景
当页面内容超出画布时，需要一个标准化的处理流程来决定如何调整。

#### 决策内容
建立5级溢出处理优先级策略：

| 优先级 | 策略 | 节省空间 | 何时使用 |
|--------|------|---------|---------|
| P1 | 压缩间距 | 10-30px | 轻微溢出 (<50px) |
| P2 | 字号降级 | 20-50px | 文本密集区域 |
| P2.5 | **布局模式切换** | 50-150px | 结构可转换时 |
| P3 | 隐藏次要信息 | 50-100px | 有明确次要内容 |
| P4 | 画布升级 | 全部 | 最后手段 |

#### 理由
1. 提供清晰的决策路径
2. 避免过度压缩导致可读性下降
3. 布局模式切换是高效且保持信息完整性的中间策略

### DEC-0003: 画布选择规则

**日期**: 2026-01-02  
**状态**: ✅ 已批准  
**标签**: `#layout`  
**影响范围**: 所有新工具创建

#### 问题背景
需要明确画布类型的选择标准，避免混淆 A3/A4 的使用场景。

#### 决策内容
建立明确的画布选择规则：

| 画布类型 | 使用场景 | 说明 |
|---------|---------|------|
| **A3 横向** | **默认** | 矩阵、仪表盘、画布、地图、复杂多模块布局 |
| **A4 纵向** | 仅特定场景 | 简单表单、清单、竖版线性流程 |
| ~~A4 横向~~ | **不存在** | 横向内容一律使用 A3 |

#### 代码示例
```html
<!-- 默认：使用 A3 -->
<div class="paper-a3">
    <!-- 大多数工具内容 -->
</div>

<!-- 例外：简单表单用 A4 -->
<div class="paper-a4">
    <!-- 简单竖版内容 -->
</div>
```

#### 理由
1. A3 提供更多空间，适合复杂的营销战略工具
2. 避免 A4 横向造成的模糊情况
3. 简化决策流程：默认 A3，只有明确简单时才用 A4

### DEC-0004: 样式例外规则

**日期**: 2026-01-02  
**状态**: ✅ 已批准  
**标签**: `#css` `#launcher` `#animation`  
**影响范围**: 启动器页面、圆形元素、功能性动画

#### 问题背景
在执行 Stylelint 批量清理时，误删了一些合理的样式：
- 启动器页面的卡片圆角和悬停动画
- 头像、进度环等圆形元素
- 进度条等功能性动画

需要明确区分"绝对禁止"和"允许的例外"。

#### 决策内容

**1. 启动器页面例外** (`launcher.css`)

| 允许的样式 | 值 | 元素 |
|-----------|-----|------|
| 卡片圆角 | `12px` | `.tool-card` |
| 小圆角 | `4px`, `6px` | `.card-badge`, `.mini-preview` |
| 胶囊圆角 | `99px` | `.version-tag` |
| 悬停动画 | `transform: translateY(-6px)` | `.tool-card:hover` |
| 过渡效果 | `transition: 0.2s-0.5s` | 卡片、按钮、链接 |

**2. 圆形元素例外** (全局适用)

始终允许 `border-radius: 50%` 用于：
- 头像 (`.persona-avatar`, `.user-avatar`)
- 进度环 (`.score-circle`, `.progress-ring`)
- 圆点指示器 (`.curve-point`, `.dot`)
- 圆形图标容器 (`.swot-center`, `.empathy-head`)

**3. 功能性动画例外** (工具页面适用)

允许 `transition` 用于：
- 进度条宽度/值变化
- 仪表盘指针旋转
- 折叠/展开高度变化
- 加载状态旋转/脉冲

禁止 `transition` 用于：
- 卡片悬停缩放/阴影
- 按钮悬停背景渐变

#### 代码示例
```css
/* ✅ 允许: 圆形头像 */
.persona-avatar {
    border-radius: 50%;
}

/* ✅ 允许: 进度条动画 */
.progress-bar {
    transition: width 0.3s ease;
}

/* ❌ 禁止: 卡片悬停动画 (工具页面) */
.card:hover {
    transform: scale(1.02);
    transition: all 0.3s;
}
```

#### 理由
1. 启动器页面是"入口"，需要更好的视觉引导和交互反馈
2. 圆形元素是语义化的（表示头像、状态点），不是装饰
3. 功能性动画有助于用户理解数据变化，而非纯装饰

### DEC-0005: 直角优先原则调整

**日期**: 2026-01-04  
**状态**: ✅ 已批准  
**标签**: `#css` `#radius`  
**影响范围**: 全局 UI 元素（按钮、卡片、输入框等）

#### 问题背景
原有的“直角优先”（Sharp Corners First）原则过于严格，导致一些必要的圆形或微圆角设计（如头像、状态指示器）被错误地强制改为直角，影响了视觉体验和用户习惯。

#### 决策内容
1.  **废除“禁止圆角”的绝对规则**。
2.  **允许使用微圆角**：允许 UI 元素使用 `var(--radius-sm)` (2px) 和 `var(--radius-md)` (4px) 以增加界面的亲和力，同时保持专业感。
3.  **保护圆形元素**：明确保护头像、圆形按钮、指示点等必须为圆形的元素 (`border-radius: 50%`)。
4.  **禁止大圆角**：继续禁止非必要的装饰性大圆角 (>8px)，以维持严肃的工具风格（Launcher 除外）。

#### 代码示例
```css
/* ✅ 允许: 微圆角 */
.btn {
    border-radius: var(--radius-sm); /* 2px */
}

/* ✅ 允许: 标准圆角 */
.input-field {
    border-radius: var(--radius-md); /* 4px */
}

/* ✅ 允许: 完全圆形 */
.avatar {
    border-radius: 50%;
    /* 或 var(--radius-full) */
}

/* ❌ 仍然禁止: 装饰性大圆角 (除非特定组件) */
.card {
    border-radius: 20px; 
}
```

#### 理由
1.  纯直角设计在某些场景下显得过于生硬。
2.  微圆角是现代专业界面的通用标准，不影响“纸面”隐喻。
3.  防止过度纠偏导致的设计破坏。

## 📥 如何添加新决策

### AI 代理操作步骤

1. **遇到规范未覆盖的情况**时，先询问用户
2. **用户确认方案**后，在本文件添加新决策记录
3. **分配决策ID**: `DEC-XXXX` (递增)
4. **填写完整模板**
5. **更新决策索引表**
6. **根据影响范围**更新相关文档

### 决策ID规则
- 格式: `DEC-XXXX` (4位数字，从0001开始)
- 按时间顺序递增
- 已拒绝的决策保留ID，不复用
